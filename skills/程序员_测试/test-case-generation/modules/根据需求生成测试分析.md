# 根据需求生成测试分析

## 目标

由 AI/用户根据**需求文档**写出 `test_analysis_content.json`（思维导图树形结构），并满足产品级后置自查。

## 路径 A 与路径 B（需求从哪来）

| 场景 | 第一步 |
|------|--------|
| **路径 B**：用户已给本地需求文件 | **直接使用其绝对路径**，无需 MCP；需求文件须已存在于磁盘。 |
| **路径 A**：用户只给需求号（`story_num`） | **必须先**按下文「路径 A」调用 MCP → 落盘 → 再得到「需求文档路径」。**禁止**未调接口就按需求号编造正文。 |

---

## 路径 A：从需求号经 MCP 拉取并落盘

当用户只提供**需求号**时，按下列顺序执行；**不得跳过 MCP 拉取**直接编造需求正文。

### A.1 调用 MCP 获取需求详情

- **MCP 服务**：`user-hundsun`
- **工具**：`get_story_info`
- **调用前**：在 `mcps/user-hundsun/tools/get_story_info.json` 核对参数 schema（必填以描述为准）。
- **典型参数**（`call_mcp_tool` 的 `arguments` 中须**写全 schema 要求的字段名**，勿省略凭据键名）：

  - `question`：简短说明意图，例如：`获取需求单详细信息用于生成测试分析`
  - `story_num`：用户给出的需求号；多个时用**英文逗号**分隔（与工具说明一致）
  - **`devops_access_key`**：**必按 schema 传入**（与当前 DevOps/MCP 环境匹配的访问密钥）。值从 MCP 服务端配置说明中获取，**随 MCP 请求提交**；无可用密钥且网关允许时，可传空字符串 `""` 作为占位并重试（见下）。**禁止**把真实密钥写入需求 Markdown 或代码注释。
- **响应**：一般为 JSON，含 `code`、`message`、`data`（需求详情列表或结构化字段）。若 `data` 为空，向用户说明未查到该需求号，**不要**继续杜撰落盘内容。

### A.2 将需求内容写入本地文件

- **需求简述（必做）**：在落盘前根据 MCP 返回的标题、产品目标或验收要点，归纳 **≤10 个字** 的**需求简述**（见 [路径与编码约定.md](路径与编码约定.md)）；须避免路径非法字符，且同一仓库内宜唯一可辨。
- **产品目录（必做）**：**先判定 `<Product>`**——优先依据 MCP 返回的产品/项目字段；若无则按用户指定的 **`--product`** 或与任务上下文一致；**`<Product>` 文件夹名须与 `public/pre_docs/<产品>/`、脚本 `--product` 一致**。
- **需求目录（必做）**：在 `<your_workspace>/<Product>/` 下建 **`<需求号>-<需求简述>`**，测试分析与用例全部落在该路径。**完整路径**为 **`<your_workspace>/<Product>/<需求号>-<需求简述>/`**（**禁止**多需求共用一个输出目录）。
- **需求文件路径**：在**上述需求目录内**创建 Markdown，文件名为 **`<需求号>-<需求简述>.md`**（与需求子目录 stem **完全一致**），绝对路径形如：
  - `<your_workspace>/HUI/202602033246-弹框居中可拖拽/202602033246-弹框居中可拖拽.md`（示例中 `<Product>` = `HUI`）
- **内容**：将 MCP 返回的有效信息整理为 **Markdown 需求文档**，建议包含：
  - 标题行：`# 需求 <需求号>`
  - 元信息：产品/模块、状态、负责人等（若接口有返回）
  - **需求描述 / 验收标准 / 备注** 等正文，保持原文信息不丢失
- **编码**：UTF-8。

落盘完成后，与路径 B 一样进入下文「输入与输出」及后续 pre_docs / 后置自查 / 主脚本流程。

---

## 输入与输出

| 类型 | 说明 |
|------|------|
| 输入 | 需求文档路径（**须为本地已存在文件**）；`--product <产品名>`；可选 `public/pre_docs/<产品>/` 下参考（如 `context.md`） |
| 输出 | `test_analysis_content.json`（中间产物；与需求文档同处**`<需求号>-<简述>`** 独立目录，简述 ≤10 字，见 [路径与编码约定.md](路径与编码约定.md)） |

## 前置（pre_docs）

- 使用 `--product` 时，主脚本会展示 `pre_docs/<产品>/` 下文本文件作为参考（根目录默认在工作区 **`public/pre_docs/`**）。
- 建议分文件：`analysis_context.md`（分析思路）与 `cases_context.md`（用例示例），或单文件 `context.md` 内分章节。

## 后置自查（post_docs）

- **必须**：`post_docs/<产品>/测试分析checklist.xlsx`（优先）或 `测试分析checklist.md`（根目录默认 **`public/post_docs/`**）。
- 可选总清单：`post_docs/测试分析checklist.md`（同章节以产品为准）。
- 未通过时：根据报告修改 `test_analysis_content.json`，再执行：

```text
python scripts/generate_from_requirement.py "<需求绝对路径>" --output-dir "<输出目录绝对路径>" --product <产品名> --analysis-post-check-only
```

通过后脚本会继续生成 XMind、用例等（与完整流程一致）。

## 主脚本命令示例

在**该需求目录**下结合 `pre_docs/<产品>/`（`--product`）编写 `test_analysis_content.json` 后，**`--output-dir` 必须与需求文件所在目录相同**：

```powershell
cd <your_workspace> ; python <skill_root>/scripts/generate_from_requirement.py "<your_workspace>/<Product>/<需求号>-<需求简述>/<需求号>-<需求简述>.md" --output-dir "<your_workspace>/<Product>/<需求号>-<需求简述>" --product <产品名> --no-preview-doc
```

若已写好 `test_analysis_content.json` 且仅需快速过分析自查再继续生成：

```powershell
python <skill_root>/scripts/generate_from_requirement.py "<your_workspace>/<Product>/<需求号>-<需求简述>/<需求号>-<需求简述>.md" --output-dir "<your_workspace>/<Product>/<需求号>-<需求简述>" --product <产品名> --analysis-post-check-only
```

路径 B 时将上述占位路径换为用户的**实际需求文件绝对路径**与对应 `--output-dir` 即可。

## 内容格式

见模板 [`test_analysis_content.json`](../../../../public/templates/test_analysis_content.json)。要点：`topic_data` 为树形，**所有值必须是对象**（叶节点用 `{}`，**禁止**字符串值）。路径与命令格式见 [路径与编码约定.md](路径与编码约定.md)。

## 安全与合规

- MCP 返回内容可能含内部信息，落盘路径应落在用户指定或项目约定工作区内。
- 勿将 `devops_access_key`、`blade_api_token`（及 `api_token` 等）写入需求 Markdown 正文；凭据仅出现在 MCP 调用参数、**`public/config.json`** 或受控密钥库中。
